# Runtime acceptance evidence design

Use the existing build-support facade for a point-in-time source/client/server comparison. Source revision and dirty status come from Git in the active working directory. Client identity comes from build metadata. Daemon identity comes from the actual process handling an existing read-only Ping, including current_exe rather than a channel symlink. No agent or provider is created to query identity.

Pong carries optional serde-default server_runtime. Older peers omit it and yield unknown. Remote TUI requests Ping during connection and retains the actual identity separately from human-readable server_version. Keepalive pongs without identity must not erase a previously observed identity. Local in-process TUI uses its own build identity as the serving process.

Only valid hexadecimal hashes can match. Proven source/client/server revision differences or observed dirty states report mismatched even when another observation is absent. Matched requires complete authoritative cleanliness. Mutable cached build metadata does not prove final binary cleanliness, so its `cleanliness_verified` is false and `server_dirty` is unknown. The opt-in immutable workflow below can establish source cleanliness. SSH source paths are never inspected as local paths. Disconnect clears daemon identity, while same-connection keepalives preserve it. JSON extends the existing version fields additively. Version rows reuse display-cell ellipsis truncation.

Acceptance: helper tests cover matching, mismatching, dirty and missing/invalid observations. Protocol tests cover old and modern Pong. Public CLI acceptance must query an isolated serving daemon without changing the shared daemon, and TUI tests must cover retained remote identity and bounded version rows. Final full crate gates and independent review remain required before archive.

## Opt-in immutable local builds

`JCODE_IMMUTABLE_BUILD=1 scripts/dev_cargo.sh build --profile selfdev -p jcode --bin jcode` selects Linux-only local offline/locked compilation. It never loads remote config or falls back to a remote/mutable build. Unsupported bubblewrap, namespace restrictions, unsafe input selection or missing cached dependencies fail the build. Default builds remain unverified.

`scripts/immutable_build.py` reuses the wrapper's raw no-follow Git file selection. It excludes credential names, refuses tracked private inputs and symlinks, and reads local Cargo.lock even if ignored. Limits: 64 MiB/file, 512 MiB total and 4096 selected files. It hashes HEAD, raw blob bytes, paths and executable modes, compares those captured bytes with HEAD, then seals transport memfds. No original-checkout writes or Git mutations occur.

A sealed archive avoids bubblewrap argument limits. A trusted outer bootstrap extracts producer-validated regular relative paths into a namespace-private tmpfs. Before Cargo starts, an inner namespace binds `/src` read-only, creates private PID/proc namespaces, removes capabilities and disables further user namespaces. No compiler has a writable source alias, including parent `/proc/*/root` paths. Compilation writes outputs, temporary files and private devices only. Host same-UID process injection, kernel compromise and malicious toolchain/output-cache poisoning remain outside this source attestation boundary. Chmod alone is not the immutability claim.

The sandbox exposes system libraries/toolchain and Cargo registry/git caches read-only, not host home or credentials. It sanitizes inherited environment, preserves selected local `.cargo/config[.toml]` and internal compiler-wrapper paths, and refuses external Cargo path dependencies/source directories. Outputs use `target/immutable/<source-fingerprint>/` (or the equivalent beneath explicit `CARGO_TARGET_DIR`) to prevent cross-snapshot cached local artifacts. Toolchain/system/cache inputs remain trusted, not fully reproducible or cryptographically attested.

Build metadata reads hash, dirty, date and fingerprint from `/jcode-immutable` after checking read-only `/src` and attestation mounts. It ignores caller provenance flags, including forced Cargo `[env]` overrides. `SOURCE_FINGERPRINT` records snapshot identity. Clean source, verified clean client and verified clean actual serving daemon remain required for `matched`. Later source edits and stale serving hashes are mismatched. Old peers or mutable builds remain unknown where cleanliness is unproven.

Acceptance: `python3 scripts/test_dev_cargo_cwd.py` compiles an offline fixture for clean/edit/revert and checks hash/dirty/fingerprint, ignored-secret isolation, caller/config forgery, internal dependency/config handling, external paths and symlinks. Actual compiler-wrapper attacks cover write/chmod/rename/remount/nested namespaces/proc aliases. A synchronized host edit starts after rustc begins and confirms compiled bytes remain captured snapshot bytes. The mutable edit→compile→revert regression remains unverified. Real Jcode isolated-daemon clean/edit/stale acceptance is separate, never claimed from fixture results.
