## Evidence, 2026-11-20 (coordinator, implemented directly after two workers were lost to server restarts)

- 1.1: `OvernightManifest.supervisor_start_time` and `heartbeat_at` (serde default, so old manifests load). `heartbeat_at` records when this supervisor took ownership (start or restart resume). It is a timestamp only: owner liveness is pid plus start time, and no heartbeat task exists (a periodic manifest write collided with the try-locked manifest lock, so it was removed).
- 1.2: `overnight/restart.rs::reconcile_run` consumes `revalidate_task_admission` (persisted authorization, remaining attempts/runtime/spend, dependencies, cancellation, workspace), `ensure_task_dispatch` (authoritative monetary capability gate) and owned-work settlement via the session-control store. Unsettled predecessor/child work, a recorded limit breach, missing authority, unloadable policy, non-Ready admission and a denied dispatch gate all end `Interrupted` with a `run_interrupted` reason. Candidate ownership is only saved after every gate passes. Hooked from server boot (`server.rs`, `reconcile_on_startup`).
- 1.3: new terminal `OvernightRunStatus::Interrupted` ("interrupted"), labelled in core, prompts and the TUI status label. Resumed runs show `run_resumed` in the event log.
- 1.4 tests (`overnight::restart::tests`, 11, including stale-save revival, cancel-vs-interrupt and cancel-during-resume races, single reconcile claim, and own-pid ownership): eligible task resumes with the wake time 30h past; CancelRequested becomes Cancelled and the dispatch closure panics if reached; live owner (pid 1 with matching start time) leaves the manifest byte-identical, a start-time mismatch (pid reuse) is not an owner; disabled policy, unloadable policy and denied dispatch stay Interrupted; a much broader policy cannot revive an exhausted attempt budget and never rewrites the persisted authorization; legacy run without task authority is Interrupted.
- 2.1: `cargo test -p jcode-app-core --lib -- --test-threads=1 overnight` and `-p jcode-overnight-core` pass (coordinator gate 2026-11-20: overnight-core 27, app-core overnight 86, tui overnight 27, workspace clippy `-D warnings` clean, validate valid).
- Known limit: in production `ensure_task_dispatch` still fails closed (no spend enforcer), so an otherwise eligible run is `Interrupted` with that reason until a chargeable executor exists. The resume path itself is covered with an injected gate.
- Known limit: a restart that kept the same pid (exec reload) is treated as no live owner on purpose, because the supervisor task did not survive.
- Collateral fix: the visible `/overnight` start now only blocks on auth for routes that resolve to a login provider (`resolved_route_auth_block`). Wave 4's unclassified-route block refused the `omni` profile and broke 3 TUI tests; supervised loops still block unclassified routes.
- Review fixes applied (reviewer notes in `scratch/applyall/review-reconcile-overnight.md`): `Interrupted` is protected from stale `Running` saves in `save_manifest_at` (test `interrupted_run_cannot_be_revived_by_a_stale_save`); a concurrent cancel wins over the interrupt and no false `run_interrupted` event is written (`a_concurrent_cancel_wins_over_the_interrupt`); one reconcile claim per run per process; this process owns a run only while it really supervises it (usage registry or resumed set), so exec reloads still reconcile; a cancel landing during the ownership save wins and no `run_resumed` is recorded; an unreadable start time still counts as a live owner; any reconciliation error ends `Interrupted`; resume refuses to substitute a different provider route than the persisted one.
- Known limit: a resumed supervisor reuses `run_supervisor`, which is not resume-aware. It starts with the first-turn prompt, rewrites preflight, and wake-time pacing (`next_step`) can move it to wrap-up immediately. Resume itself is only reachable once a chargeable executor passes `ensure_task_dispatch`; until then every eligible run ends `Interrupted`.
- Known limit: `/proc` start time identity is Linux-only; elsewhere only pid liveness is checked.
- Known limits from review (not fixed, latent while the dispatch gate denies): admission runtime counts wall clock since `started_at` including downtime; resume pacing uses `target_wake_at`; visible (non-supervised) runs left Running by a restart are not closed; `Interrupted` runs with unsettled owned work have no later cancel path via the run; two server processes sharing one home could both resume (claims are per process); a legacy manifest with no start time and a reused live pid stays Running (fail safe); `kill(pid,0)` counts zombies as alive; `resolved_route_auth_block` has no test through `start_overnight_run` (covered by the TUI start tests); `Reconciled::Interrupted` is also returned for an unresolved cancel settlement while the manifest stays CancelRequested.
- Known limit: `start_overnight_run` never sets `task_admission` today (no unattended task authority is granted at start), so in production every stale supervised run reconciles to `Interrupted` ("no persisted task authorization") or `Cancelled`; the Resume path is exercised only with fixtures that carry persisted authority.
