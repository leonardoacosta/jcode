## 2. Durable tracking and recovery

- [x] 2.1 Reuse existing background-task persistence/UI records to store MCP server and authorization-context identity references, remote task ID, original call/session association, status, timestamps, TTL, and result/error. Add `mcp_task_tracking` tests for restart/reconnect, no original-call replay, identity mismatch, and persistence failure before exposing a task handle.
  Evidence: `mcp/task_tracker.rs` over `TaskStatusFile.mcp_task` (`background/model.rs`); server identity is a SHA-256 fingerprint, never a credential. Tests `task_tracker_tests::mcp_task_tracking_{register_persists_running_record_without_owner,register_fails_closed_when_persistence_fails,resume_after_restart_polls_without_replaying_the_call,identity_mismatch_is_unresolved_and_never_reaches_the_server}`; `tasks_wire_tests::mcp_task_tracking_call_registers_a_background_task_and_never_replays`.
- [x] 2.2 Implement polling from persisted task state. Honor `pollIntervalMs`, bound retry backoff, stop at terminal status/expiry, and retain last-known state during disconnect. Test lost notifications, transient transport errors, stale notifications, server restart, and expired/not-found tasks.
  Evidence: polling honors `pollIntervalMs` (default 5s, clamp 1s..300s), doubles per failure to 300s, caps at time to expiry, stale snapshots never regress state. Tests `task_tracker_tests::mcp_task_tracking_{poll_interval_defaults_to_5s_and_is_clamped,unavailable_server_backs_off_then_recovers,lost_notification_polls_at_the_suggested_interval,resume_of_an_already_expired_task_does_not_poll,resume_with_unknown_task_marks_not_found_and_stops}`; `mcp_task_tracking_completes_through_polling_against_a_live_stub`.
- [x] 2.3 Integrate confirmed cancellation and cancellation races with the existing background-task UI. Test cancellation requested versus confirmed, completed/failed races, transport loss, and refusal to cancel terminal tasks.
  Evidence: `McpTaskTracker::cancel` returns `CancelOutcome::{Confirmed,ServerFinished,Requested,Unacknowledged}`; `bg cancel` routes MCP tasks to the tracker (`tool/bg.rs`). Tests `mcp_task_tracking_cancel_is_requested_then_confirmed_by_the_server` and the cancel race tests in `task_tracker_tests.rs`. Known limit: cancel does not abort the polling loop; polling continues until the server reports terminal.
- [x] 2.4 Surface MCP task kind, remote state, available result/error, `input_required`, expiry, and unresolved-server state in the existing task UI. Verify keyboard operation, empty/loading/error states, and narrow-terminal row truncation without adding a separate task view or ledger.
  Evidence: existing `bg` list STATUS cell, status details and metadata show MCP kind, remote state, result/error, expiry and unresolved state, with bounded server text (`truncate_cells`, `bound_json`). Tests `tool::bg::tests::mcp_task_tracking_{status_and_list_show_remote_state,list_cells_fit_their_columns}`. The TUI info widget reads bus events, not the status file, so MCP tasks appear there through the ordinary background started/completed events (`mcp:<server>:<tool>`); no separate task view was added.

  Evidence: `NotificationSession` task hints (`accept_task_hint`, `TASKS_METHOD`), `ingest` routes `notifications/tasks` to the sink reading only the task id; `McpTaskTracker` implements `TaskHintSink` and `hint` matches exact server and remote id. ## 5. Review follow-up (independent review `scratch/applyall/tasks-review.md`)

- [x] 5.1 Blocker and majors fixed with regression tests. B1: `Mcp-Name` carries the task id for `tasks/get|update|cancel` over HTTP (`remote_tests::tasks_requests_carry_the_task_id_as_mcp_name`). M1: an equal-second terminal snapshot is accepted and a terminal state is never replaced (`mcp_task_tracking_equal_second_terminal_snapshot_is_accepted`, `..._terminal_state_is_never_replaced_by_a_working_snapshot`). M2: the identity is stamped on the connection at connect time (`McpHandle::identity`), `resolve` uses it, and the workspace check is gone from `resolve` (`mcp_task_tracking_identity_comes_from_the_connection_config`). M3: a non-shared server never opts in (`mcp_task_tracking_non_shared_server_never_opts_in`). M4: only a caller with a tracker declares the extension (`mcp_task_tracking_plain_call_tool_never_declares_the_extension`, `..._manager_without_tracker_does_not_declare_the_extension`). M5: `advertises_tasks` requires the modern era. M6: `bg cancel` on an unresolved task closes it locally as Lost and says the remote task was not cancelled (`mcp_task_tracking_unresolved_task_can_be_dismissed_without_contacting_a_server`, `..._cancel_with_identity_mismatch_never_reaches_the_server`). M7: failed-task error text is capped at 300 cells (`mcp_task_tracking_failed_error_text_is_bounded_in_the_status`).
- [x] 5.2 Minors fixed: m1 hint spacing floor (`..._hint_flood_keeps_minimum_poll_spacing`), m6 bounded server ids in errors plus `kind_label` strips backticks and bidi controls (`..._kind_label_drops_backticks_and_bidi_controls`), m9 atomic status writes, m10 a task handle for any method but `tools/call` is an error, m12 disabled servers do not resolve.
- [x] 5.3 Known limits, not fixed in this change: (m2) the listen restart notify is one shared `Notify`, so with several listening servers a new task may restart another server's stream, which only delays hints and polling still completes; (m3) task hints need the server to also have `notifications` configured, tasks-only servers are polled; (m4) a call that lands before server startup finishes installing the tracker declares no extension and runs synchronously; (m5) the identity does not include the OAuth account; (m7/m8) an oversized inline payload is replaced by a marker without `result_truncated`, and expiry uses the local clock against the server `createdAt`; (m11) per-project entries in `~/.claude.json` are user-owned and not stripped; (m13) MCP tasks are not counted in the info widget's running counters and keyboard and narrow-terminal behavior is covered only by `truncate_cells` width tests; only servers opted in to `notifications` or `tasks` are probed with `server/discover`.
