## 2. Reconnect, bounds and policy

- [x] 2.1 Restore supported subscriptions after reconnect, then reconcile subscribed resources and opted-in catalogs with ordinary reads/lists. Add tests for missed, duplicated, reordered notifications, changed capabilities and failed reconnects.
  - Evidence: `legacy_establish_subscribes_then_reconciles_without_wake`, `reconnect_reestablishes_with_new_capabilities`, `failed_subscribe_is_recorded_and_uri_stays_unaccepted`, `duplicate_and_reordered_notifications_converge`. Reconnect itself reuses the existing owner/pool reconnect, which builds a new client and so a new engine that runs `establish`.
  - Dropped hints: `pump_reconciles_after_a_final_dropped_burst_with_no_later_message` (a burst that overflows the inbound slot with no later message still reconciles via the drop signal); `InboundDrops` notifies the pump instead of relying on the next message.
  - Same limit as 1.3: reconciled prompts/resources land in `NotificationStatus` only; tools reconcile reaches the registry.
- [x] 2.2 Add per-server keyed deduplication/coalescing, bounded queues and rate limits without blocking interactive MCP requests. Test burst, overflow and independent-server fairness.
  - Evidence: `dispatcher_coalesces_by_key`, `dispatcher_overflow_drops_newest_and_flags_reconcile`, `dispatcher_rate_limit_rolls_over_after_a_minute`, `dispatchers_are_independent_per_server`, `inbound_slot_discards_until_installed_and_never_blocks_when_full`, `burst_coalesces_into_single_refresh_and_wake`. The slot uses `try_send`, so reader tasks never block interactive requests.
  - Wake cooldown (per server, default 60s, `wake_cooldown_secs`): `wake_cooldown_defers_then_releases_per_server` (fake clock via `drain_at`: deferred wake is kept, a flood of the same class adds nothing, release after the window, next one waits again), `default_wake_cooldown_is_sixty_seconds`, `pump_releases_a_deferred_wake_on_its_own_timer` (no further message needed).
- [x] 2.3 Add per-server notification allowlists that separately govern catalog/resource refresh and agent wakes. Ensure unknown or unlisted notifications cannot wake an agent and payloads/content never become trusted instructions. Test configured and denied cases.
  - Evidence: `refresh_and_wake_allowlists_are_independent`, `unlisted_class_is_ignored_and_cannot_wake`, `wake_only_resource_outside_config_is_ignored`, `wake_carries_identifiers_only_and_never_payload`, `config_roundtrips_and_defaults_are_opted_out`, `protocol_tests::mcp_server_notifications_default_to_opted_out_and_parse_allowlists`.
  - Trust boundary: opt-in is honored only from global/user config. `protocol_tests::project_local_config_cannot_opt_in_to_notifications` (`.mcp.json`, `.jcode/mcp.json`, `.claude/mcp.json` in the project are stripped with a warning while a global entry is honored) and `project_definition_shadowing_a_global_server_does_not_inherit_its_opt_in`.
  - Server-chosen names: `sanitize_server_name` (control chars, newlines, quotes, spaces become `_`; max 64 chars) tested by `sanitize_server_name_strips_control_chars_and_bounds_length`, `wake_request_server_name_is_sanitized_by_the_engine` and, for item id, text and `created_by_session`, `runner_mcp_wake_tests::hostile_server_name_cannot_inject_lines_or_overflow_item_text`.
- [x] 2.4 Route permitted events through existing session admission or the ambient schedule/queue path. Coalesce duplicate pending wakes and test absent/busy/revoked sessions plus ambient disabled/paused behavior. Reuse current queue ownership and do not add a parallel scheduler.
  - Evidence: `cargo test -p jcode-app-core --lib -- ambient::runner notify_session mcp_wake_for_busy mcp_notification_tests` 22 passed (run twice). Router: `runner_mcp_wake_tests` (identifier-only ambient item, session target, ambient-disabled reported `Dropped`, duplicates return `Coalesced`, revoked session reported `Dropped("target session admission is revoked")` and nothing queued even with ambient enabled, hostile name). Absent: `runner_tests::mcp_wake_for_absent_session_fails_delivery_without_panicking`. Idle: `mcp_wake_resumes_idle_session_with_identifiers_only`. Busy: `server::client_actions::tests::mcp_wake_for_busy_live_session_queues_soft_interrupt` (an MCP wake item for a busy live session lands in its soft-interrupt queue, same path as other scheduled tasks). Ambient paused/disabled: `mcp_ambient_wake_stays_queued_while_session_wakes_are_claimed`. Reuses `ScheduledQueue` and `deliver_scheduled_direct_item`; no new scheduler.
  - Fail closed: a permitted wake with no handler installed is not counted as delivered. `permitted_wake_without_handler_fails_closed_and_is_reported` and `handler_reported_drop_is_not_counted_as_a_wake` (counter `wakes_dropped`, per-class `errors["wake:<class>"]`, logged warning). `WakeHandler::wake` now returns `WakeOutcome` (`Queued`/`Coalesced`/`Dropped(reason)`).

  - Flake note: `server::client_actions::tests::notify_session_runs_scheduled_task_immediately_for_idle_live_session` failed once under parallel load (timing), passes alone and in two further runs; not touched by this change.
