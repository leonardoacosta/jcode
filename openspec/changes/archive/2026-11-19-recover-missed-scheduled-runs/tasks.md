  - Limit: a revoked `Spawn` parent is suppressed only when its session control record exists and is non-runnable. Origin-generation suppression applies only when the target is the creating session. The stale check is not atomic with the wake: a revocation landing between the check and the notify still wakes the target.
  - Accepted limits: (a) a whole batch is claimed `Dispatched` up front, so a mid-batch crash marks not-yet-attempted items `uncertain` (fail-closed, noisy). (b) The ack generation is best-effort: read after delivery, `None` for unregistered or spawn-child sessions. (c) A wake arriving for an id that is `Dispatched` creates a second item with the same id; delivery is serial, so `settle` hitting the live claim first is benign. (d) Terminal items share the queue file, so an older binary would treat them as ready: do not downgrade with unresolved history. (e) A `Dispatched` claim is abandoned when its owner (`pid:starttime:nonce`) is gone or its start time differs, or after 1 hour regardless; it then becomes `uncertain` and can be retried or cancelled.
