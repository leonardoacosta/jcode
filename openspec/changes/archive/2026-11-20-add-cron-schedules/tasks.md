## Known limits left by review (minor)

- A cap cancels every active turn of the target session, and a delivery into a live session that is already mid-turn completes when that turn ends. If that session is the user's own, an unrelated concurrent turn can be cancelled or counted. Turn-scoped cancel and completion need a per-turn identity the registry does not carry.
- Token usage is observed after each provider response, so one response can overshoot a cap. A new turn started later in the same session is not blocked by a reached cap.
- A recurring item's `origin_generation` is stamped at admission, so the creator-generation revocation check does not apply to it.
- `schedule list` does not flag a persisted definition whose zone or cron no longer parses; the tick skips it silently.
- A spend-capped schedule never starts and each occurrence is recorded `budget_unavailable`.
- Ambient-target recurring items are queued but the ambient agent, not the delivery path, consumes them.
