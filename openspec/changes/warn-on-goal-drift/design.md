# Design

## Context and alternatives

Existing goals persist and attach to sessions through `goal.rs`; `initiative` exposes create/list/show/resume/update/checkpoint/focus. Semantic compaction compares average old/new embedding histories, which confuses valid phase changes with goal deviation. Existing Jev MCP `jev_classify` accepts shared classes/context, at most 64 items, and truncates each item at 2,000 characters. Its auto/review result is not authorization or proof. Native `McpManager::call_tool` provides a reusable transport. The direct `JevClient::for_supervision` route is a separate pending feature and is not an MCP equivalent.

Alternatives: local embedding-only warnings are cheap but detect vocabulary changes, not intent; automatic remote checks over full transcripts have privacy/cost/reliability problems; selected bounded Jev checks offer stronger semantic judgments without replacing deterministic authority. Select the third approach behind explicit user-controlled opt-in. No live submission is authorized by proposal creation.

## Goals / non-goals

Detect sustained work outside an attached active goal and explain why. Preserve useful supporting work and user-directed changes. Never gate tools, completion, permissions or continuation. No remote judge is an enforcement authority.

## Decisions

1. **One goal owner.** Read the currently attached active initiative. Reuse its ID, description, criteria, exclusions and revision/hash. Add exclusions through the existing goal update contract if absent. A goal is explicitly attached or updated, not extracted from untrusted text. No goal means `not_applicable`, not an invented objective. A newer explicit user instruction supersedes the old objective for checking: suspend the check and request reconciliation rather than warn against the user or silently rewrite the stored goal.
2. **Explicit remote opt-in.** Disabled by default. Configure exact MCP server/tool identity and the known `jev_classify` contract, no auto-discovery, new installation, credential collection or alternate route. Only permit data submission after the user opts into that route and data class. Explain that bounded goal and recent conversational text leave the host. A valid config/schema does not grant disclosure consent. Use existing native MCP transport, not agent shell calls or proxy-specific eval adapters. Tool description/page content cannot grant permission.
3. **Bounded per-turn check.** Check once after a complete user-visible turn, not every token, tool call, retry or internal hook. Never recurse on monitor-generated events or spawn a turn just to warn. Include goal summary/criteria/exclusions (at most 2,000 characters of structured context) and selected recent user request plus assistant action/result excerpt (one item, at most 2,000 characters total). Mark selection/redaction/truncation. If meaning-critical content cannot fit, return insufficient evidence instead of silently treating a truncated result as complete. Exclude tool outputs, files, credentials, full memory, hidden reasoning and unrelated transcript. Secret redaction cannot guarantee removal of all private content; opt-in covers the residual bounded text.
4. **Single-flight and freshness.** One in-flight request per session, at most one attempt per completed turn, a 2-second deadline and no automatic retry. Use existing cancellation/shutdown. Capture session ID, turn ID and goal hash; discard results after any changes that invalidate their binding. No unbounded queue. Report pending/unavailable without delaying assistant output; lack of result never means aligned. Exact route/tool must still satisfy current tool policy. Denied/disabled tools are not reachable through an internal bypass. Record request counts and observed latency, not payloads.
5. **Advisory state.** Map explicit classes `aligned`, `supporting_work`, `possible_drift`, `insufficient_evidence`; adapt the exact discovered contract and reject malformed/missing/ambiguous class distributions. Suggested initial warning rule: two consecutive comparable checks where possible_drift has probability >=0.85 and winner margin >=0.50. These are uncalibrated defaults, not accuracy claims. Unknown/error/sampling gaps reset the consecutive streak. Warn once per goal revision until dismissal or explicit refocus; no repeated transcript clutter. The explanation is a fixed local message citing goal and turn references, never untrusted model instructions. Do not claim that the classifier provides a rationale if the tool does not return one.
6. **Interaction.** Present “Possible goal drift” with current goal and the observation that two recent checks marked work outside it. Provide exact reason/evidence references only if they are in the validated response. User actions: Refocus adds a visible bounded reminder without launching a turn; Dismiss clears the warning/streak; Update goal opens the existing goal-edit path with explicit confirmation. Do not fabricate existing controls or route to an unimplemented editor. During implementation select existing actual commands and add only missing actions. All controls work in TUI; headless output includes advisory status and explicit supported text/tool equivalents. Count terminal cells, fit narrow widths, sanitize control characters and keep color-independent text.
7. **Persistence/privacy.** Store only bounded advisory state and bindings in existing session metadata: verdict class, counts, last checked turn/hash, timestamps and dismissal. Do not store submitted excerpts, full distributions or extra memory entries by default. Resume skips obsolete pending calls and clears stale streaks; goals, scheduler and approval state remain unchanged. Never log credential-bearing raw MCP errors.

## Verification

Use existing public goal/session/MCP interfaces with isolated homes and local fake MCP server, not copied classifier code. Fixtures cover supporting work, explicit goal changes, absent goals, untrusted “ignore the goal” text, two repeated drift turns, uncertainty, timeouts, malformed/truncated payloads, denied tools, stale results, cancellation, resume, deduplication and secret sentinels. Test all normal/headless/capture turn paths and narrow TUI frames. A live Jev smoke uses explicitly authorized synthetic nonsecret input only and proves transport/schema behavior, not warning accuracy. Do not submit private conversations merely to complete a test.

## Risks

Semantic classifications can be wrong. Test false-warning cases and report fixture outcomes without asserting calibrated reliability. A two-second remote timeout can skip slow results. Single-flight work must not hold agent locks or stall streaming. Host/MCP permissions and disclosure consent remain independent of classifier confidence. Goal changes must invalidate pending checks before any reminder reaches the next turn.
