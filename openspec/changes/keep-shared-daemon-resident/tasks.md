- Decision for the user (M4): idle exit now applies only to `--temporary-server` processes. A non-systemd, non-temporary server (plain client auto-spawn, `jcode self-dev` spawn through the Shared lifetime) no longer idle-exits after 5 minutes. This follows the settled "the shared daemon never idle-exits" decision literally, but the proposal's "self-development servers MAY idle-exit" is only honoured for servers started with `--temporary-server`. If self-dev auto-spawned servers should keep idle exit, they need to be spawned as temporary (owner PID) or a supervised/unsupervised split must be added.
- Known limit (M2): work presence reads the process-wide ambient queue and background task directory, so an ownerless temporary server sharing `JCODE_HOME` with the user's daemon stays alive while the user has a pending schedule or a running task. Owner-PID death is still honoured first. `list()` also finalizes orphaned task files as a side effect every 10s.
- Known limit: client prompts and live turns are still admitted while shutting down; only new swarm workers and ambient claims are refused. The registry publisher is not stopped by shutdown and `ServerRegistry::save` is not atomic, so a status read racing a write can fail (pre-existing pattern). Registry cleanup checks pid liveness, not socket liveness. The temporary shutdown path ignores the drain result and exits 44.
- Known limit: after a failed `exec` the process exits 42 as before.
