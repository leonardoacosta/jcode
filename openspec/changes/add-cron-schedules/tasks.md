# Cron schedules execution contract

All tasks are implementation work, not completed by authoring this proposal. `tasks.md` is the only execution ledger. Execute the dependencies `recover-missed-scheduled-runs` and `keep-shared-daemon-resident` first, then refresh their contracts and the P06 budget contracts before implementation. Do not add a second daemon, scheduler loop, or queue.

## 1. Existing schedule-path inventory and recurrence model

- [ ] 1.1 Inspect current schedule tool registration and callers, ambient queue/persistence/runner ownership, existing queue history and crash-recovery interfaces, and the exact contents of `keep-shared-daemon-resident`. Record the exact files and types to extend; verify the shared ambient runner remains the sole scheduler owner and do not rely on unmerged working-tree source.
- [ ] 1.2 Inspect `reconcile-usage-budget-accounting` and `enforce-overnight-cancellation-and-limits` implementation/specs after their prerequisites. Record which ownership IDs, counters, reservations, and hard-enforcement inputs are authoritative. Do not infer monetary reservation from estimated or post-request-only usage. If no supported hard monetary enforcement primitive exists for a provider, specify and test `budget_unavailable` without adding a parallel accounting system.
- [ ] 1.3 Define persisted schedule and occurrence states, stable schedule/occurrence ID format, cron grammar supported by installed dependencies, IANA zone validation, bounded preview count, bounded history retention, global concurrency configuration/default, and migration-compatible JSON representation. Document deterministic gap/overlap resolution and behavior when timezone database rules change. Test the pure occurrence calculator before queue integration.

## 2. Persisted definitions, occurrence calculation, and controls

- [ ] 2.1 Extend the existing schedule input and `schedule` tool contract to create named recurrence definitions with explicit cron, IANA timezone, missed-run policy, per-schedule concurrency and optional token/spend caps. Preserve existing one-shot inputs and output semantics. Reject invalid cron/zone/limits without persisting any change. Add focused app-core tool tests for both legacy one-shot compatibility and validation failures.
- [ ] 2.2 Persist schedule definitions and state through the existing ambient schedule persistence boundary. Use the store's transactional lock/reload/write path. Persist occurrence decisions, idempotency key, next occurrence, pause state, and bounded recent run outcomes before making work runnable. Add restart round-trip and stale-manager transaction tests; do not create a new state file/service unless the existing store cannot safely contain this state, in which case stop and revise the design rather than silently forking persistence.
- [ ] 2.3 Implement local-calendar cron iteration with explicit zone resolution. Add pure tests for spring gap skip, fall overlap earlier-instant-only, zone rule update for unclaimed future dates, and a non-DST zone. Verify preview and dispatch call the same calculator and that local timestamps map to stable schedule occurrence keys.
- [ ] 2.4 Implement missed-run policy decisions for downtime and forward jumps: skip records each missed item, run-once coalesces to the latest, catch-up queues the oldest up to its positive bound and records the remainder skipped. Add tests asserting durable decisions precede dispatch, plus restart and backward-clock tests proving recorded keys are not duplicated.
- [ ] 2.5 Extend existing `schedule` tool controls for list, pause, resume, and next-run preview. Keep preview read-only. Show ID, expression, zone, next local/UTC time, policy, pause state, limits, and recent outcomes. Add tests for persistence across restart, preview non-mutation, pause with active work, and resume applying missed-run policy.

## 3. Bounded dispatch, budgets, and recovery integration

- [ ] 3.1 Integrate recurring occurrences with the existing ambient runner and `recover-missed-scheduled-runs` claim/ack/history path. Associate the same occurrence key with the durable queue item and history. Test crash before acknowledgment as uncertain without automatic redelivery; crash after acknowledgment but before task completion must not create a second delivery of that occurrence. Delivery acknowledgment must not be presented as task success.
- [ ] 3.2 Enforce configured per-schedule and global active-run limits in the existing runner. A full limit must leave due items durably pending without losing identity; releasing capacity must wake the runner. Add tests for each limit, concurrent schedule mutations, fairness among due schedules, and no duplicate starts. Pausing blocks new admission but does not claim active tasks are stopped.
- [ ] 3.3 Bind token/spend accounting to the existing overnight ownership and P06 budget enforcement contract using the occurrence key as stable run attribution. Enforce caps before new admission and during active execution, deduplicate replayed usage, and reconcile reservations after restart. Add tests for exhausted cap, provider without authoritative monetary enforcement (`budget_unavailable` and no start), active-run limit cancellation with unsettled children, duplicate usage event, and crash after reservation before settlement. If existing P06 artifacts lack a required enforcement operation, update this change's dependency/design boundary instead of implementing an independent budget ledger.
- [ ] 3.4 Verify future recurrence, pause/resume, and history survive restart under `keep-shared-daemon-resident` and that the shared daemon remains the sole active scheduler. Add a regression test or isolated lifecycle test using existing server/runner test harnesses; do not spawn a second daemon or touch user runtime state.
