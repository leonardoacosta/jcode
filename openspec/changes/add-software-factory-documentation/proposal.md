## Why

Jcode's research on open agent harnesses and AI software-factory engineering is broad enough to be durable architecture knowledge rather than a chat-only conclusion. The repository needs one navigable entry point that distinguishes observed implementation, proposed direction, and external research while linking the factory lifecycle to dedicated reference pages.

## What Changes

- Add a `docs/factory/` documentation section with `README.md` as its index and introduction.
- Record the factory lifecycle from intent through specification, planning, execution, verification, delivery, and learning.
- Add dedicated pages for architecture, artifacts and provenance, workers and orchestration, isolation, gates and approvals, evaluation and regression, observability, governance, feedback, open harnesses, Jcode mapping, and sources/limitations.
- Use consistent claim labels: `observed`, `proposed`, `external research`, and `open question`.
- Link the new index from the existing documentation entry point without changing runtime behavior.

## Capabilities

### New Capabilities

- `software-factory-docs`: Evidence-bounded documentation of Jcode's AI software-factory model and lifecycle.

### Modified Capabilities

- `repository-docs-index`: Add a navigation entry for the factory documentation section.

## Non-goals

- No runtime, tool, provider, orchestration, or command-center implementation changes.
- No claim that proposed factory capabilities already exist.
- No copying of private transcripts, credentials, or unsupported benchmark claims.
- No new documentation framework or microsite runtime.

## Impact

Adds documentation under `docs/factory/` and updates the existing documentation index. The change is documentation-only and should preserve all active implementation work and unrelated OpenSpec changes.
