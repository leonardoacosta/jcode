Harness audit / research brief

Improve the contracts, not the tool count.

Most of the workflow machinery is already here. The useful next steps make discovery truthful, long-running work interruptible, and review evidence machine-readable, without building parallel frameworks.

03

What survived the audit

Separate source-confirmed gaps from advertised contracts and documentation leads.

  1. 01

    Discovery is the clearest user-visible gap. Candidate construction drops skill descriptions; native and skill suggestions share color logic. Preserve typed identity and authoritative source metadata through the shared candidate/cache boundary. Source + runtime

  2. 02

    Overnight cancellation is only observed between turns in the inspected path. The supervisor checks cancellation around coordinator turns; the active monitored turn is awaited, not interrupted. Source only

  3. 03

    Headless review should reuse what exists. empryo advertises a review verdict/exit contract, but the inspected Jcode surface already has JSON and NDJSON runs. Define scope and inconclusive outcomes before adding a contract. CLI help + Jcode source

  4. 04

    Prompts are not permission boundaries. Plan/review instructions request analysis-only behavior; this pass did not establish executor-enforced read-only capabilities. Trace permissions before making a security claim.

  5. 05

    Do not copy automation ceremony wholesale. No universal reviewer/arbitrator, second task ledger, new scheduler daemon, or auto-approval transition. Keep the user’s external-action boundaries intact.

05

A bounded sequence for later proposals

Priority is a research recommendation, not approval or implementation readiness.

01 / First

Typed selector metadata

Prove source, description, collision, refresh, remote compatibility, and display-cell behavior in real TUI frames.

02 / Next

Responsive overnight stop

Cancel a deliberately long active turn; verify child work, final state, restart safety, and no further launches.

03 / Then

Structured headless review

Reuse current JSON/NDJSON. Specify pass, fail, inconclusive, stale revision, cancellation, and clean machine output.

Next: reconcile with existing workflow evidence/evaluation specs, then choose one bounded Feature/OpenSpec slice. Planning/continuation and swarm-recovery contracts need further tracing; conditional feedback, arbitration, locator, and recurring-routine work need a confirmed gap or concrete use case.
