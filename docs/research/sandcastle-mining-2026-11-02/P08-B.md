## 1. Reject schema-valid output as review authority
- Source: `PlanSchema`, `planJson`, `PlanSchema.parse(JSON.parse(planJson))` validate planner JSON, not correctness of a review or permission to execute its contents.
- Counterexample: valid `{issues:[{number:1,title:"x",branch:"wrong-target"}]}` can name the wrong target. A valid verdict can likewise describe an obsolete revision.
- Jcode already has JSON/schema validation in `HarnessClient.runStructured` (`sdk/typescript/src/client.ts:1434-1468`), so copying tagged output or importing Zod adds no missing authority boundary.
- Candidate delta: require revision/check-evidence binding and explicit inconclusive/cancel/budget outcomes in the existing headless-review owner, not merely a verdict enum.
- Acceptance: schema-valid PASS for another revision or stale checks must not satisfy review acceptance. Malformed JSON must remain distinct from a negative review.
- Confidence: high on distinction; no runtime review acceptance verified.

## 2. Disposal is not remote cancellation
- README symbols: `SandboxHandle.close`, `[Symbol.asyncDispose]`, `SandboxRunOptions.signal`; docs separately promise teardown and run cancellation with handle reuse.
- Jcode also separates observation cleanup (`events().stop`, `sdk/typescript/src/client.ts:1083-1093`) from server cancellation (`cancel`, `:689-692`). Iterator disposal only removes listeners and queued frames.
- Counterexample: a consumer exits its iterator after a timeout while the server turn continues spending tokens or using tools. Conversely, cancelling a turn must not imply permission to delete shared resources.
- Candidate delta: add disposal-without-cancel and cancel-without-dispose negative cases to existing SDK contract tests, beyond positive cancellation coverage in P08-A.
- Acceptance: dispose observer → turn remains independently observable; explicit cancel → only the selected turn stops; disconnect must not silently become cancellation.
- Confidence: high from local source, medium for Sandcastle documented guarantees.

## 3. Do not universally swallow observer failures
- README `onAgentStreamEvent` explicitly swallows callback exceptions so forwarding failures cannot kill a run. Jcode calls `options.onEvent?.(event)` before terminal handling (`sdk/typescript/src/client.ts:1373-1375`).
- Counterexample: a callback can implement an audit or policy requirement, not optional logging. Swallowing its failure silently can erase required evidence while work continues.
- Candidate delta: classify observation-only forwarding separately from policy/tool callbacks before adopting P08-A's telemetry isolation idea. Preserve visible failure and document remote-turn continuation.
- Acceptance: throw on text and `turn_done`; outcome must identify the observer failure without claiming server cancellation or losing the terminal disposition. Do not adopt blanket catch-and-ignore.
- Confidence: high on direct invocation; exact server continuation needs runtime evidence.

## 4. Concurrency and iteration caps are not cost/deadline bounds
- Source symbols `MAX_ITERATIONS = 10`, `MAX_PARALLEL = 4`, `acquire`, `release`, `Promise.allSettled` bound scheduling, not model tokens, elapsed time, or reviewer retries.
- Source invokes reviewer after `result.commits.length > 0` and discards its returned value; a fulfilled implementer result does not establish review PASS.
- Jcode `run()` terminates on `turn_done` or throws on `error` (`sdk/typescript/src/client.ts:1423-1429`); transport completion alone is not a revision-bound review verdict.
- Candidate delta: existing structured-review contract must distinguish completed transport from passed review and carry budget exhaustion independently. Do not import Sandcastle's orchestration loop as an acceptance gate.
- Acceptance: reviewer failure/nonverdict/budget exhaustion cannot become PASS because implementation fulfilled; a hung reviewer needs an explicit bounded cancellation outcome.
- Confidence: high for inspected example; no claim about all Sandcastle SDK internals.

## 5. Explicit no-adopt for browser/voice authority
- Cached evidence above establishes run, stream, output and disposal contracts, not browser tab/goal scoping or voice capture consent. Generic `signal` cannot establish either.
- P08 explicitly requires those boundaries and unavailable-service/help-handback checks (`docs/plans/PRODUCT_ROADMAP.md:223-226`); keep `add-browser-voice-boundary-acceptance` as owner.
- Acceptance remains Jcode-specific: rejected cross-tab actions, scoped help return, explicit capture/intent, unavailable service. No Sandcastle-derived implementation recommendation without direct evidence.
- Confidence: high on evidence insufficiency, not a claim that Sandcastle lacks such functionality.
