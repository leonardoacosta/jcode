## 1. Explicit agent/model/effort selection rather than inferred model identity
- Mechanism: `run({ agent: claudeCode("claude-opus-4-8", { effort: "high" }), sandbox: docker() })` separates agent configuration from execution environment. README extracted lines 212-219; https://github.com/mattpocock/sandcastle#all-options . The cached real `.sandcastle/run.ts` example also passes `sandcastle.claudeCode(...)`, `docker()`, and `name: "Planner"` explicitly (cache lines 432-440).
- Jcode differs: model selection is a many-route interactive catalog. `PickerOption` already carries `provider`, `api_method`, `available`, `detail`, and estimated reference cost at `crates/jcode-tui/src/tui/mod.rs:2118-2127`. Favorites already persist at `crates/jcode-tui/src/tui/app/inline_interactive.rs:245-282`. An `available` flag is not a health result.
- Bounded adoption: keep effective route/model identity separate from display label, favorite state, and credential presence. Show unknown evidence explicitly. Do not import Sandcastle's literal model defaults or add billable catalog probes.
- Dedupe: **already owned** by `openspec/changes/improve-model-picker-browsing/proposal.md:12-22`. Treat this as supporting rationale/acceptance detail, not a new proposal. P06 owns provider diagnostics.
- Acceptance: select the same model through two routes and different efforts; detail and current-selection marker must track the chosen tuple. Credentials-present/never-used must not render healthy. Opening/filtering causes zero inference requests. Verify narrow-width frames.
- Confidence: high on documented mechanism and Jcode fields; medium on UX transfer. No Sandcastle model-picker implementation was observed.

README extracted lines 110-118 and 1520-1524; https://github.com/mattpocock/sandcastle#config-directory-sandcastle . This is documented onboarding, not proof of an interactive wizard.

- Bounded adoption: finish onboarding with one resolved provider/model or one exact recovery command, reusing provider-doctor wording. Retain import origin without exposing credential values. Do not copy Sandcastle's `.env` workflow or require users to generate repository files.
- Dedupe: **already owned** by `openspec/changes/clarify-first-run-provider-setup/proposal.md:12-17`. Do not create another setup feature or silently convert credential presence into live verification.
- Acceptance: no credentials, skipped import, import failure, and imported-but-expired credentials each show truthful status and an actionable command. Import in progress must not claim failure or ask users to log in again. No automatic browser launch or billable probe.
- Confidence: high on cache documentation and current recovery paths; runtime first-run flow untested.

## 3. Make the path-resolution base visible when configuration fails
- Mechanism: `run()` distinguishes `cwd` from `promptFile`: documentation explicitly says `promptFile` resolves against `process.cwd()`, **not** `cwd`. README extracted lines 258-264; https://github.com/mattpocock/sandcastle#all-options . This is a useful counterexample: a visible project directory does not identify every setting's resolution base.
- Jcode differs: its config facade documents `~/.jcode/config.toml` or `$JCODE_HOME/config.toml`, with environment overrides, at `crates/jcode-base/src/config.rs:1-4`. Session metadata separately has `working_dir` at `crates/jcode-tui-session-picker/src/lib.rs:110-128`. These are distinct sources, not interchangeable config scopes.
- Bounded adoption: display the effective setting source/resolution base in existing setup or diagnostic detail when a user must repair configuration. Derive it from existing resolution evidence; do not invent a new precedence layer, executable config, or universal configuration inspector.
- Dedupe: `openspec/changes/configure-task-and-worktree-policy/proposal.md:18,49` already owns effective-value provenance for task/worktree settings. Any P09 display should consume that P08 evidence, not reimplement it. Existing first-run proposal owns provider recovery; a narrow source-detail addition needs coordinator scope review.
- Acceptance: compare default home versus `JCODE_HOME` plus an environment override, with a different session working directory. The displayed source must match the actual effective value. Missing files show the attempted base; paths are visible locally but no secrets enter frames/logs or provider requests.
- Confidence: high on documented distinction; medium on fit. Exact user-facing resolver hook remains to be selected. Do not claim Jcode has Sandcastle's `promptFile` bug.

## 4. Stable run/session identity is a prerequisite, not proof of resumability
- Mechanism: `run()` returns `result.iterations` with optional `sessionId`, `result.branch`, and commit identities; `name` adds a run label in logs. README extracted lines 198-201 and 271-272; https://github.com/mattpocock/sandcastle#programmatic-api . The actual cached `.sandcastle/run.ts` example uses a named Planner, but does not demonstrate an interactive resume picker.
- Jcode differs: `SessionInfo` already stores stable `id`, parent, title, working directory, provider/model, timestamps, status, and previews at `crates/jcode-tui-session-picker/src/lib.rs:110-140`. `SessionFilterMode::CurrentDir` is explicitly directory-scoped at `:37-43`.
- Bounded adoption: preserve stable IDs behind friendly titles and directory/source badges during sorting/filtering and resume. Treat a provider's optional session ID as metadata only unless a tested continuation path exists. Do not build a Sandcastle-style resume facility from the field name.
- Dedupe: **already owned** by `openspec/changes/restore-resume-picker-redesign/proposal.md:13-18`, which covers compact metadata rows, sorting, split preview, paging, and display-cell truncation. Add collision/identity cases to its checks, not another redesign. Existing `show-resolved-worker-model` archive supplies related display evidence, not session-resume completion credit.
- Acceptance: duplicate titles across directories/providers, missing optional model/session metadata, filtered/reordered rows, and deleted sessions must never resume a different ID. Long Unicode titles retain one logical row at narrow widths. A saved external transcript is not labeled live/continuable without supporting evidence.
- Confidence: high on identity fields; medium on cross-product lesson. Sandcastle's optional `sessionId` does **not** establish checkpoint restoration or safe cross-provider continuation.
