## 1. Validate a finite work selection before starting workers
**Observed:** R defines `PlanSchema`, parses JSON inside `<plan>` from planner stdout, rejects missing/invalid output and exits when `issues.length === 0`. `MAX_ITERATIONS = 10` bounds outer planning rounds.
**Jcode difference:** `OvernightManifest` persists identity, timing and status (`crates/jcode-overnight-core/src/lib.rs:47-63`); supervisor reloads the manifest and checks cancellation before a turn (`crates/jcode-app-core/src/overnight.rs:267-281`). Neither observation proves task-level admission. Existing policy tasks explicitly require deterministic readiness and restart revalidation (`openspec/changes/configure-task-and-worktree-policy/tasks.md:6-9`).
**Bounded adoption:** retain native task records, but admit only a validated finite selection with exact repository/task identity, dependency result and authorization scope. Persist the selected attempt identity before dispatch. On restart, re-evaluate eligibility instead of replaying an old planner answer or treating elapsed time as permission.
**Acceptance:** malformed/missing planner data starts zero tasks; empty selection exits cleanly; duplicate task IDs cannot yield two live attempts; changed authorization or cancelled dependency blocks resumed dispatch with a reason. Task limits remain finite across restart, not reset per process.
**Dedupe:** refinement of admission + policy + restart proposals. Do not add Sandcastle, XML-tag parsing or another task ledger. Confidence: high on source pattern, medium on proposed integration pending caller inventory.

## 2. Enforce a runtime concurrency slot, release it on every outcome
**Observed:** R implements `MAX_PARALLEL = 4`, `acquire`, `release`, a FIFO `queue`, `try/finally` and `Promise.allSettled`. One rejected issue is logged without suppressing sibling outcomes.
**Jcode difference:** P05 itself records that persisted records and guidance do not establish enforced concurrency (`docs/plans/PRODUCT_ROADMAP.md:172-174`). Current supervisor cancellation check occurs at a turn boundary (`crates/jcode-app-core/src/overnight.rs:267-281`).
**Bounded adoption:** enforce existing configured limits at the actual native dispatch boundary, with per-attempt ownership. Waiting tasks must remain cancellable. After a crash, reconcile live children before replacing slots. Persist attempts/outcomes, not an in-memory semaphore count.
**Acceptance:** enqueue five instrumented tasks at limit two, observe at most two executing; fail one, observe a slot released and siblings recorded; cancel a waiter, observe no dispatch; restart while two children survive, observe no extra admission or duplicate attempt.
**Dedupe:** belongs in cancellation/limits + restart reconciliation. Do not copy hard-coded limits or Sandcastle's process-local queue as durability. Confidence: high on source, medium on native boundary coverage.

## 3. Classify reuse state separately from branch freshness
**Observed:** W replaces `throwOnDuplicateWorktree` across `run()`, `createSandbox()`, `SandboxFactory` and `WorktreeManager.create`. Reuse distinguishes staged/unstaged/untracked changes from local/remote divergence. Only clean, strictly-behind worktrees receive `git fetch origin <branch>` then `git merge --ff-only`; dirty, diverged or offline cases remain intact with a reason. Its dirty-reuse default is explicitly permissive.
**Jcode difference:** SDK `create` derives sibling `<repo>-worktrees` (`crates/jcode-sdk/src/worktrees.rs:105-131`), rejects an existing destination (`:138-144`) and invokes non-force `git worktree add -b` (`:148-152`). Policy proposal already covers root containment, identity, safe reuse and manual cleanup (`openspec/changes/configure-task-and-worktree-policy/tasks.md:11-14`).
**Bounded adoption:** add a read-only reuse classification to that existing policy work: exact repository/branch/base, owner/live consumer, uncommitted state, ahead/behind/diverged and freshness unknown. Preserve the primary checkout. Reuse only already-authorized owned worktrees. Keep refresh separately authorized, never infer permission to fetch/modify from an old task or a clean status.
**Acceptance:** fixture matrix covers clean equal, strictly behind, ahead, diverged, staged/unstaged/untracked, offline and active consumer. No case loses local commits/files; unauthorized refresh makes zero remote calls; disallowed roots/symlinks fail before mutation; repeat admission selects the same authorized workspace or reports why not.
**Dedupe:** enrich existing worktree-policy tests, not another allocator. Reject automatic dirty reuse, automatic fetch, repository-local layout, reset/clean and implicit worktree creation. Confidence: high on ADR/SDK differences, medium on current upstream implementation because ADR was not runtime-tested.

## 4. Keep execution result, useful output and review evidence separate
**Observed:** R uses `result.commits.length > 0` to trigger a reviewer, retains the implementer's `result`, then derives `completedIssues` from fulfilled executions with commits. The review return value is not inspected as a semantic approval. `completedBranches` then feeds a merger agent. These are example orchestration choices, not proof that commits mean accepted work.
**Jcode difference:** native task cards already distinguish before/after data and validation evidence (`crates/jcode-overnight-core/src/lib.rs:176-228`), and `save_manifest`/`load_manifest` persist run records (`crates/jcode-app-core/src/overnight.rs:734-739`). Reuse those records rather than importing commit-count completion.
**Bounded adoption:** record separate attempt outcome, changed/no-op result and review/validation evidence against the exact resulting revision. Restart must invalidate stale review when the revision changes, and must not replay external effects merely because local review completed. A useful no-op may succeed with evidence, while commits alone never imply completion/publication authority.
**Acceptance:** rejected worker, successful no-op, commits with failed review and interrupted review produce distinct truthful states; reviewer failure cannot become accepted merely through nonempty commits; changed revision invalidates prior approval; repeated restart does not repeat merge/publish actions. No merge or publication runs without its own authority.
**Dedupe:** refine restart + task admission contracts, coordinate shared handoff evidence with P04. Do not adopt the project's automatic merger or reviewer invocation as approval. Confidence: high on source distinctions, medium on precise native evidence schema needs.

## Limits and recommendation
- Prioritize the worktree classification matrix and per-attempt concurrency/restart tests in existing proposals. All four mechanisms overlap existing scope, so no new OpenSpec change is justified.
- Sandcastle evidence inspected does not establish durable triage state, persistent queue replay, exactly-once external effects or daemon crash recovery. Those remain Jcode requirements, not borrowed guarantees.
- Validation performed: read public source/ADR, compared exact current Jcode ranges and proposal tasks/archive; one uncached public URL retrieved, no installs/login/private-source upload. No runtime tests run because this assignment is research only.
- Blockers: none for this report. Implementation still requires the existing readiness/authorization gates and full caller inventory; upstream ADR execution behavior remains unverified.
