Orchestration

Plans, lanes, swarms, queues, review gates, and Orca coordinate accountable work without owning product truth.

Previous Next

What this layer does

The orchestration layer decomposes work, serializes conflicting resources, assigns agents, and collects artifacts. It does not decide that implementation evidence is true without downstream validation.

Evolution

documented: the approved DAG and command lifecycle specify dependency order and ownership keys; inferred: Orca and swarm details are grouped here as coordination mechanisms.

Daily use

A change request becomes a DAG node or task list, workers receive bounded ownership, and completion returns artifacts plus validation rather than a bare success claim.

Interfaces

Inputs are typed requests and constraints. Outputs are task assignments, owner/resource locks, completion reports, and escalation when evidence is missing.

Ownership

Owned by the coordinator for the current run. Product maintainers own acceptance criteria and final disposition.

Failure boundaries

Stale plans, conflicting mutable ownership, correlated self-review, or workers reporting done without evidence.
