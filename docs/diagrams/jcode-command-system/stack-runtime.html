Layer · runtime

Runtime

Processes, terminals, browsers, sockets, sandboxes, and remote hosts execute tool effects under lifecycle control.

Previous Next

What this layer does

The runtime layer provides the execution envelope for commands and long-lived work. It keeps sockets, background tasks, browsers, and local servers observable and cancellable.

Evolution

documented: install notes and runtime-verification guidance distinguish a built binary from the long-lived daemon; inferred: Atlas runtime groups terminals, browser sessions, and hosts as one execution boundary.

Daily use

A focused validator runs with a timeout, a browser journey captures console/network state, or an isolated socket tests a Jcode build without disturbing the shared daemon.

Interfaces

Inputs are tool effects and lifecycle options. Outputs are exit codes, logs, screenshots, task status, and receipts.

Ownership

Owned by the local harness or deployment host. Passing runtime execution is not the same as passing product acceptance.

Failure boundaries

Orphaned processes, port collisions, stale worktrees, interactive commands, or checking the wrong daemon binary.
