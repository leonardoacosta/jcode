Layer · model

Model

Risk, capability, latency, and cost classify work before a provider is selected; deterministic work can bypass models.

Previous Next

What this layer does

The model layer is a routing boundary. It chooses a suitable model or no model based on role requirements and available credentials, and it should not invent silent fallback.

Evolution

documented: routing and OAuth smoke evidence describe provider availability checks; inferred: cost and latency are shown as routing inputs when the sources do not provide a complete policy table.

Daily use

Simple deterministic checks run as scripts. Implementation or review work is routed to a model matching the role, and unavailable providers cause visible failure or reroute with disclosure.

Interfaces

Inputs are task role, risk, required tools, auth state, and model registry. Outputs are a selected route, a no-model path, or a fail-closed error.

Ownership

Owned by routing policy and runtime availability. The selected model owns its response, not the evidence that proves the change.

Failure boundaries

Unavailable auth, cheap-first retry loops, self-review for high-risk work, or hidden provider fallback.
