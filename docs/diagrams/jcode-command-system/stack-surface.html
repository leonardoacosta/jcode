Surface

Commands, chat turns, palettes, side panes, and docs turn human intent into an addressable request.

Previous Next

What this layer does

The surface layer is the only layer directly controlled by the user. It captures prompt text, command names, visible project state, and approval boundaries before any scheduling or mutation begins.

Evolution

documented: README and command docs show the CLI/chat entry point; inferred: the Atlas groups palette and side-panel affordances here because they initiate or explain work rather than execute it.

Daily use

A user asks for a repo change, chooses a command surface, and sees the intended action before Jcode assigns work. No Pi, Codex, or Claude execution is asserted here beyond documented UI and CLI entry.

Interfaces

Inputs are prompts, slash-command style intents, current working directory, visible links, and explicit approvals. Outputs are normalized requests for orchestration.

Ownership

Owned by the product surface and command documentation. Repository truth still lives in source files and OpenSpec artifacts, not in a screen label.

Failure boundaries

Ambiguous intent, hidden active project, stale visible state, or a destructive action that is not surfaced to the user.
