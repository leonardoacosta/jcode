Chapter 04 · role routing

Spend thought
where it matters.

Some command work requires no model at all. Model-requiring roles should be classified before execution, not escalated only after a cheap attempt fails.

Design hypothesis; tier labels inferred

01 / LADDER

Four source-native outcomes with inferred tier names.

0

Model-free

Schema validation, hashing, locking, scheduling, budget arithmetic, metric comparison, tests, and KEEP/REVERT authority.

1

Low-risk worker (economical label inferred)

Extraction, classification, bounded mechanical edits, formatting, and low-risk summarization with deterministic checks.

2

Normal implementation agent (mid-tier label inferred)

Semantic synthesis, normal implementation, autoresearch candidates, and routine review where a ratchet or test suite corrects defects.

3

Frontier judgment

Artifact authoring, evidence matrices, security/schema implementation, adversarial review, and failure remediation with broad blast radius.

02 / ROUTE

Risk before price.

Diagram fallback: deterministic work uses no model. Bounded low-risk work uses an economical worker and checks. Semantic normal work uses a mid-tier model. High-risk work uses frontier capability plus cold review, cross-provider only when risk is high.

Anti-pattern: “Start cheap, escalate on failure” can waste the first attempt’s tokens, latency, and context. Jcode pre-classifies the role and risk, then evaluates the routing hypothesis.
