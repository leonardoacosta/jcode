Tools

Typed tools turn model decisions into observable reads, edits, browser actions, messages, schedules, and integrations.

Previous Next

What this layer does

The tools layer is where intentions become constrained operations. Schemas bound parameters, approvals protect external effects, and results return observations rather than proof of acceptance.

Evolution

documented: tool call schemas and the command-system validator show typed inputs and observable results; inferred: grouping every integration under this layer is an Atlas abstraction.

Daily use

Jcode reads files, applies patches, runs focused commands, or reports to swarm through named tools whose arguments are visible in the transcript.

Interfaces

Inputs are model or coordinator decisions. Outputs are file reads, edits, command results, browser snapshots, messages, and schedules.

Ownership

Owned by the harness/tool implementation. The agent owns choosing a safe tool and interpreting output honestly.

Failure boundaries

Malformed calls, hidden side effects, unbounded shell output, missing integrations, or treating a tool result as end-user acceptance.
