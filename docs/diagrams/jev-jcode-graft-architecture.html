Adopt build now

Foundation primitives. Replace LLM-call-with-text-parsing patterns with typed Jev judgments.

#1 · ADOPT · LOW EFFORT · HIGH IMPACT
evaluate tool
Replaces "ask LLM → parse text → hope valid" with typed probabilities. ~$0.0002/call vs ~$0.003. ~300ms vs ~2s latency.
→ Path A: Native Rust tool (~200 lines, reqwest + Serde)
→ Path B: Bundle evaluate Go binary as built-in MCP
POST https://api.typesafe.ai/v1/systemone { state, model: "jev-latest", questions: { is_urgent: { type: "noul", instructions: "..." } } } → { answers: { is_urgent: { noul: 0.91 } } }
#2 · ADOPT · MEDIUM EFFORT · HIGH IMPACT
Jev-driven context compaction
Never rewrites text. Jev scores each tool call for relevance. ~$0.002 vs ~$0.02 for LLM summarization.
→ Add JevCompactor to agent/compaction.rs
→ Steal fast-jev-compaction's 5-step algorithm
→ Fall back to LLM summarization if Jev unavailable
1. Pair tool_use ↔ tool_result; pin recent N 2. Fit state into 25k tokens (staged truncation) 3. Per call: 2 Noul Qs — "keep call?" "keep result?" 4. Batched into parallel Jev requests 5. Rebuild message list; no orphaned results
#3 · STEAL · HIGH EFFORT · HIGH IMPACT
Jev browser element selection
jev-ultrafast: 7.1s flight search. 101 browser calls instead of 1,092. One Jev request picks operation + element.
→ Add action="jev_select" to tool/browser.rs
→ Snapshot DOM → indexed element table
→ Speculative fan-out: operation + target in one request
→ Only TYPE_TEXT triggers small LLM
page → DOM snapshot → [{index,role,label,value}...] → TypeSafe: operation={CLICK|TYPE|SELECT|...} + click_target={[1]Button,[5]Link,...} + type_text_target={[2]Input,[3]Search,...} → Browser executes matching element

Consider prototype

Validated prior art but needs Jcode-specific adaptation. Prototype before committing.

#4 · CONSIDER · MEDIUM EFFORT
Model tier routing
Saves 40-60% API costs. Jev picks Fast/Balanced/Strong per-turn. jev-router proven on Claude Code + Codex.
→ Provider middleware, not proxy
→ Intercept first request per turn
→ Tier map: per-provider config
→ Fail-open: unavailable Jev = current model
#5 · CONSIDER · HIGH EFFORT
Worker supervision (Foreman)
10 Jev Noul questions per cycle. Catches stuck/off-track workers before token waste. Deterministic policy decides.
→ Periodic Jev assessment on swarm workers (30s)
→ 10 dimensions in one request per cycle
→ Start passive: observe, don't intervene
→ Risk: Jcode swarm > Foreman single-worker
#6 · CONSIDER · MEDIUM EFFORT
Jev code review
6-stage pipeline across 5 dimensions with calibrated confidence. 10-50× cheaper than LLM review.
→ Pre-screen: Noul risk matrix per diff hunk
→ Score >0.7: route to full LLM review
→ Score <0.7: Jev-only with confidence scores
→ Integrate with existing /review skill

Bundle low risk

#7 · BUNDLE · LOW EFFORT · LOW IMPACT
Shell history
Tab → Jev picks matching command from history. ~$0.0001/completion. Zero risk.
→ Bundle Go binary or re-implement as jcode shell-history
→ Zsh widget registered on jcode init

Integration Relation Map — each proposal's effect on existing Jcode crates:

# Relation Meaning
#1supplementAdds new evaluate tool alongside existing tools. No existing code modified.
#2replaceSwaps LLM summarizer in compaction.rs with Jev-based tool-call pruning. Existing compactor kept as fallback.
#3extendAdds action="jev_select" to existing browser.rs. All current actions remain.
#4extendMiddleware layer before provider.rs dispatch. Pass-through when Jev unavailable.
#5extendBackground observer on turn_loops.rs. Starts passive — reports, doesn't intervene.
#6supplementPre-screening layer before existing /review skill. Jev screens, LLM reviews flagged hunks.
#7supplementNew sub-command or binary. Zero interaction with existing crates.
