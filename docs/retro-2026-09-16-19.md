# Retro: work tally and session friction, September 16-19, 2026

Source corpus: the 13 entries in `~/dev/journal.md` and their source sessions. 94 Jcode
sessions ran in the Sept 16-19 window (102 including earlier-started ones); 80 map to
journal projects. Totals: 1,370 human asks, ~26.6k assistant messages, ~26.7k tool calls.

Method: per-project session mapping from raw `~/.jcode/sessions/*.json` records, command
prefix mining, friction vocabulary counts, and a five-worker lens audit (outcome integrity,
discovery/access, execution efficiency, durable environment, automation candidates) with
every finding re-verified against primary session evidence by the coordinator.

## Hotspots (vetted, ranked by leverage = impact x recurrence / effort)

### 1. Wholesale AGENTS.md names skills that resolve nowhere

- Pattern: systemic
- Evidence: `fleet-sync-lanes`, `azure-devops-cli`, `deploy-loop`, `bicep-module-conventions`,
  `ado-pipeline-scripting`, `docs-site-conventions`, `health-check-probes` are referenced in
  `brown/wholesale/AGENTS.md` but missing from `~/.agents/skills`, `~/.jcode/skills`, and
  repo-local skill dirs (verified directly). Sessions `zebra`, `turkey`, and `evergreen`
  each independently re-inventoried the same gap.
- Impact: every wholesale session re-discovers missing skills; the steering file advertises
  capability the runtime cannot load.
- Intervention: check (preflight validating every AGENTS.md skill name against installed
  indexes), effort S, risk LOW, confidence HIGH.
- Success signal: wholesale preflight reports zero unresolved skill references; sessions
  stop repeating the installed-versus-listed inventory.

### 2. Azure/ADO environment setup re-typed inline despite existing wrappers

- Pattern: systemic
- Evidence: 605 `AZURE_DEVOPS_EXT_PAT` export occurrences across 8 sessions and 179
  `AZURE_CONFIG_DIR`/pipx-az export blocks across 6 sessions, while
  `brown/wholesale/scripts/azc` and `personal/mesh/scripts/mx-corporate-access` exist and
  cover this setup (both verified present).
- Impact: shell-quoting risk, inconsistent profile selection, wasted context on every Azure
  task.
- Intervention: pointer (document the wrappers as the first command in each repo's entry
  docs), effort S, risk LOW, confidence HIGH.
- Success signal: sessions invoke the wrapper; raw PAT/config-dir export blocks disappear.

### 3. Inline Python heredoc parsing instead of stable helpers

- Pattern: systemic
- Evidence: 955 `python3 -` / `python -` heredoc occurrences across 48 sessions, mostly
  re-parsing the same command/API output shapes.
- Impact: token overhead, fragile quoting, unversioned parsing logic.
- Intervention: tool (subcommands at existing owning entry points), effort M, risk MED,
  confidence HIGH.
- Success signal: inline heredoc parsing declines while structured output stays equivalent.

### 4. Completion claimed before acceptance evidence

- Pattern: systemic
- Evidence: 5+ automated "feedback loop never closed" flags across sessions `lion`, `horse`,
  `otter` (Sept 16); `otter` corrected agent-browser "integration" and ctate 87% -> 79%
  after delivering the report (message IDs verified); Mesh "feedback loop closed" was later
  retracted in the journal's own correction section.
- Impact: trust and rework cost; the journal now carries three correction sections.
- Intervention: reviewer standard (claims require observed artifacts; separate proposal
  approval, implementation, deployment, live acceptance), effort M, risk LOW, confidence
  HIGH.
- Success signal: correction-after-summary events decline; reports carry evidence per claim.

### 5. Fleet CI infrastructure failures recur per session

- Pattern: systemic
- Evidence: wsproxy E2E disconnects (`dromedary` #92), Neon proxy failures on self-hosted
  runners (`mizaru` #883), stale `.priceless/generated/` conformance on CI checkout
  (`crocodile` #2385, #2664), Sept 16-18.
- Impact: pilot work repeatedly appears blocked by failures outside the change; CI weakens
  as an acceptance signal.
- Intervention: check (runner-health and generated-config preflight that classifies
  infrastructure failures separately), effort M, risk MED, confidence HIGH.
- Success signal: CI identifies infrastructure failures before project review; pilots stop
  rediscovering the same blockers.

### 6. Journal conventions re-derived per session

- Pattern: recurrence (3 sessions)
- Evidence: `poodle` created `~/dev/journal.md` conventions (Sept 18 13:42Z), `tiger`
  re-derived them via head/tail/sed inspection (Sept 18 14:53Z), `evergreen` re-derived
  them again (Sept 19 10:56Z). Tool calls verified in each session.
- Impact: redundant reconstruction; inconsistent entries.
- Intervention: partially repaired already (conventions persisted to project memory Sept
  19); remaining step is a journal append command or skill, effort S-M, risk LOW,
  confidence HIGH.
- Success signal: new entries match structure without re-reading the whole journal.

### 7. CI run polling rebuilt by hand

- Pattern: recurrence
- Evidence: 121 `gh run view` occurrences across 5 otaku sessions; repeated
  `az pipelines runs show` + `bg wait` loops in `blossom`.
- Impact: latency, stale reads, duplicate status calls.
- Intervention: tool (bounded wait/status subcommand with terminal states and deadline),
  effort M, risk LOW, confidence HIGH.
- Success signal: one structured call per run instead of poll loops.

### 8. Exact-duplicate tool calls

- Pattern: recurrence
- Evidence: 38 identical name+input call groups across 16 sessions (md5 over tool_use
  inputs; a worker's looser count of 85 was corrected down).
- Impact: wasted execution and context with no new evidence.
- Intervention: reviewer standard (require changed input, prior failure, or missing output
  before repeating), effort S, risk LOW, confidence HIGH.
- Success signal: duplicate groups fall; justified reruns carry a reason.

### 9. Mesh work fragmented without durable checkpoints

- Pattern: recurrence
- Evidence: `scorpion` repeatedly remapped handoff checkpoints (Sept 16 17:38Z); `poodle`
  reconstructed completed work and corrections from the journal (Sept 18).
- Impact: re-discovery cost at every session boundary; stale completion state risk.
- Intervention: skill (mandatory checkpoint artifact at milestone boundaries), effort M,
  risk LOW, confidence HIGH.
- Success signal: a new Mesh session resumes from one verified checkpoint.

### 10. Node heap OOM on first validation attempt

- Pattern: recurrence
- Evidence: heap-limit failures in `frog`, `hog_1789531523808`, then a manual
  `NODE_OPTIONS=--max-old-space-size=6144` retry in `lizard_1789523342431` (Sept 16).
- Impact: failed runs mistaken for code failures; manual retry overhead.
- Intervention: tool (encode the memory setting in the package script; classify heap
  exhaustion separately), effort S, risk LOW, confidence HIGH.
- Success signal: first-attempt validation completes or emits a deterministic capacity
  diagnostic.

## Coverage and blind spots

- Raw mining covers Jcode session records only. External providers (claude, codex, cursor,
  opencode) were searched via session_search but not raw-mined, so their occurrence counts
  are lower bounds.
- Human-ask counts exclude `[auto]` todo reminders and system reminders, but
  overnight-coordinator machine prompts still count as asks.
- Occurrence counts include justified repeats (verification after changes); the
  duplicate-call hotspot is the only one measuring true waste.
